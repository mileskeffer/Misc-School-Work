ANSWER KEY AND EXPLANATIONS
===========================

1.  B - A function-local static is initialized when its declaration is first reached.
        The same object persists and is returned by later getInstance() calls.
2.  D - Ordinary callers cannot invoke the private constructor. The deleted copy
        operations also prevent making or assigning copies of the singleton.
3.  A - Append mode preserves existing data and puts new output at the file's end.
4.  C - Returning a reference exposes the existing singleton without copying it.
5.  B - After successful construction, the static Logger is destroyed during normal
        termination. Its destructor calls log_.close().
6.  D - Game::playGame() supplies the algorithm. Virtual dispatch invokes the added
        initializeGame(), makeMove(), endOfGame(), and printWinner() overrides.
7.  A - Player 0 is the computer. Its branch stores choices[rand() % 3] and returns;
        player 1's branch reads and validates the human's input.
8.  C - A draw does not assign a winner. With inputEnded_ still false, endOfGame()
        is false and the template begins another round with a fresh computer choice.
9.  B - Invalid input stays inside the human's validation loop. The computer's stored
        choice is unchanged; paper beats rock, so playerWon_ becomes 1.
10. D - Failed extraction sets inputEnded_ and returns. The next endOfGame() check
        stops the loop; printWinner() gives the input-closed message, not a winner.
11. C - The constructor checks !log_, writes "Unable to open log.txt" to cerr,
        and terminates the process with a failure status.
12. A - report() writes the message followed by a newline and flushes the stream.
13. B - The guard prevents repeated inclusion from redefining Logger within the
        same translation unit. The local static implements singleton lifetime.
14. D - Only the three exact uppercase tokens are normalized. Full words such as
        "rock" and mixed tokens such as "Rr" fail the exact-string checks.
15. C - S becomes s. The (human s && computer p) condition is a human win.
16. A - Paper loses to scissors. Neither a draw nor a human-winning condition
        matches, so the final else assigns playerWon_ = 0.
17. D - Initialization restores noWinner and false. It does not call cin.clear();
        reusing the object after EOF still requires usable input for human moves.
18. B - playGame() calls initializeGame() before evaluating the turn loop. The
        override replaces the initial zero player count with 2.
19. C - In a two-player game, the human has index 1, which equals playersCount_ - 1.
        After makeMove(1) returns, the template increments movesCount_, even on the
        winning turn. Draws also count, so the final value is 3.
20. A - The inherited hook checks only for a winner. Failed input leaves no winner,
        so the added inputEnded_ condition is necessary to terminate that case.

21. C - A static member function is called on the class without an existing object.
        This lets the accessor provide the first and subsequent uses of the singleton.

22. A - auto& preserves reference binding. Plain auto drops the returned reference
        and would attempt to create a Logger value using the deleted copy constructor.
        C calls the private constructor; D also attempts a forbidden copy.

23. D - "log.txt" has no directory component. The open call resolves it relative
        to the process's current working directory, which can differ from the source
        or executable directory.

24. B - The parameter is a read-only reference, avoiding an extra string copy for
        parameter passing. report() writes its contents immediately; it does not
        store the reference. Temporary strings can also bind to this parameter.

25. C - override checks the inheritance contract at compile time. For example,
        an incompatible parameter type would be diagnosed rather than silently
        creating an unrelated overload.

26. A - The added overrides are protected. Public inheritance preserves access
        to Game's public playGame(); the later protected: label does not change it.
        playGame() can invoke the protected overrides through virtual dispatch.

27. D - computerChoice_ is an owning string data member, not a pointer or reference
        into choices. Destroying the local array does not invalidate its copied value.

28. B - break exits the nearest loop. Here it exits while (true) inside makeMove(),
        after which execution continues with the computer-choice output and comparison.

29. C - A single humanChoice cannot simultaneously equal r, p, and s. The three
        winning combinations are alternatives, so they require ||. With &&, draws
        still use the earlier equality branch, but every non-draw reaches the final
        else and assigns playerWon_ = 0.

30. A - cin >> string extracts whitespace-delimited tokens rather than whole lines.
        The p remains available after the first turn reads r. Following the draw,
        the next round reads p, which beats the stipulated computer rock choice.
