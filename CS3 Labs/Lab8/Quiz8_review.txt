ANSWER KEY AND EXPLANATIONS
===========================

1.  B - The two members represent separate paint roles. This lets FullyFilled use
        one character for the border and another for the interior.

2.  D - FullyFilled delegates construction to Filled(borderChar, internalChar).
        Filled's existing getters return those separately stored values; no
        additional getter overrides are needed.

3.  A - Both getters call randomChar(), which calls rand(). Square requests a
        character for each cell, so selection happens per cell, not once per
        figure, row, or paint object. Exact random output is not predictable here.

4.  C - lot_ is a vector of Car* pointers. The constructor pushes eight requested
        cars into it; it does not keep the starter's single car4sale_ field.

5.  A - The initial index is 7. The first nextCar() computes (7 + 1) % 8 = 0.

6.  D - bought saves the pointer to the selected car. That same slot receives a
        new factory product, then bought is returned. The vector still has eight
        entries. buyCar() itself does not delete the returned car.

7.  B - Both string comparisons must succeed because the test uses &&. Merely
        liking the make is insufficient in the updated buyer implementation.

8.  C - toyotaLover() evaluates the random model argument once for the shopFor()
        call. The wanted model stays the same throughout that search.

9.  D - All cells in the first and last rows are border cells. In the middle row,
        only the central cell is interior, giving ### / #o# / ###.

10. A - delete carLotPtr->buyCar() deletes the returned purchased object after
        the replacement is installed. return then ends this buyer's search.

11. B - The figure hierarchy delegates paint behavior through Fill*. The same
        Square implementation can draw using Hollow, Filled, FullyFilled, or
        RandomFilled without adding a square subclass for each paint style.

12. C - There are 100 cells. The interior has (10 - 2)^2 = 64 cells, leaving
        36 border cells. Corners are counted once, not once per adjoining side.

13. A - Hollow calls Fill(borderChar, ' '). Filled's one-argument constructor
        passes fillChar for both roles.

14. D - The only cell has i == 0 and j == 0, so the border branch runs. A newline
        follows the single character. There is no interior cell.

15. C - Both outcomes of randomChar() return x when the two stored characters
        are identical. Random selection therefore cannot change the output.

16. B - No drawing is cached. Each draw requests characters again, but repeated
        random outcomes can still coincide; a different pattern is not guaranteed.

17. D - Figure holds a raw pointer and its destructor is empty. Deleting a figure
        does not recursively delete its fill. main() separately frees the paint
        objects after it has finished using the figures.

18. A - The object has a derived type but is deleted through a base pointer.
        A virtual base destructor provides the correct destruction chain.

19. C - buyCar() returns Car*, which may point to a Ford or Toyota. The added
        virtual destructor makes deletion through that base pointer valid.

20. B - nextCar() advances before returning: 6 becomes 7, then 0, then 1.

21. A - The loop is bounded by lotSize(), which is eight. Eight cyclic advances
        from index 2 return to index 2; no purchase or reset changes that index.

22. D - buyCar() changes the pointer at current_ but does not change current_.
        The next search continues from the following slot rather than restarting.

23. B - All buyers use the same global pointer after its first allocation.
        This is shared lazy initialization in this program, but the public
        CarLot constructor does not prohibit clients from creating other lots.

24. C - Filling the lot causes eight requestCar() calls. Two replacements add
        two more calls, so the counters sum to 10, regardless of their distribution.

25. A - The concrete factory's makeCar() allocates a new object. Random factory
        and model selection impose no rule that the make or model must change.

26. D - The buyer program uses the random vector-index expression. It does not
        call getLeastBusyFactory() from the separate carTest.cpp demo.

27. C - A static model-selection function is callable on the class without an
        instance. Toyota's constructor also uses it to choose a new car's model.

28. B - Filled's two-argument constructor is protected and available to its
        derived classes. FullyFilled exposes a public constructor that delegates
        to it. Filled's one-argument constructor remains public.

29. D - requestCar() increments the factory counter, but the program contains
        no corresponding decrement when a car is destroyed. The counter tracks
        requests added to its initial value, not the number of surviving cars.

30. A - Purchased cars are explicitly deleted, but the program omits cleanup for
        the shared lot and its remaining allocations. Raw pointer variables and
        vectors of raw pointers do not automatically delete their pointees.
